# Как устроен дневник

## Данные

Одна таблица дневника («Питание») и два справочника: продукты и наборы. Запись — это строка:
дата, приём пищи, название, порция текстом, ккал и БЖУ, плюс служебные колонки: код записи, код продукта,
количество, мерка, набор, группа, откуда пришла запись.

Есть два вида записей. **Запись по продукту** ссылается на карточку каталога: числа считаются кодом из
«КБЖУ на 100 г / 100 мл / штуку × количество». **Свободная запись** (ресторан, «половина порции») хранит
то, что посчитал бот, и правится числами.

Наборы («стандарты») — список продуктов с количествами. При добавлении набор раскрывается на отдельные записи
с общей группой, поэтому любую позицию можно поправить отдельно.

## Хранилища

| | Своя база (`sqlite`) | Google-таблица (`sheets`) |
|---|---|---|
| Где | файл `nutribot.db` в папке профиля | ваша таблица на Google Диске |
| Скорость чтения | миллисекунды | ~0,9 с из облака |
| Номер строки | постоянный id, не переиспользуется | позиция в таблице, сдвигается при удалении |
| Правка руками | через `nutribot export` и обратно нет | да, прямо в таблице |
| Приложение в Яндекс Облаке | не дотянется до базы | работает |

Выбор хранится в `.env` профиля: `NUTRI_STORAGE=sqlite|sheets`, плюс `NUTRI_DB_PATH` или `NUTRI_SPREADSHEET_ID`.

## Интерфейс хранилища

`nutricore/store.py` описывает, что должно уметь хранилище; `tests/test_store_contract.py` — исполняемый договор:
один и тот же сценарий прогоняется против обеих реализаций. Ключевые правила:

- `read_food()` возвращает `(заголовки, строки)`; порядок значений — как в заголовках;
- `food_row_numbers()` возвращает номер каждой строки в том же порядке (у таблицы это позиция, у базы — id);
- запись, правка и удаление адресуются номером строки, но логика выше всегда заново находит строку по «ID записи»;
- `read_snapshot()` отдаёт дневник, каталог, наборы и цели одним обращением — так приложение укладывается в один запрос.

Чтобы добавить своё хранилище: реализуйте эти методы и пройдите общий набор тестов.
